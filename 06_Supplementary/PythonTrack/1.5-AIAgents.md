## Concept 1 — What Is an AI Agent and Why Do We Need It?

### 1. Real-World Problem (Hook)

You ask ChatGPT:
*"Book me the cheapest flight from London to New York next Friday."*

ChatGPT says: *"I cannot browse the internet or book flights."*

You ask it:
*"What is today's stock price of Apple?"*

ChatGPT says: *"My knowledge has a cutoff date."*

The problem is clear — a plain LLM is like a **brilliant person locked in a room with no phone, no internet, no tools**. They can think deeply but cannot act on the world.

An **AI Agent** gives the LLM hands. It connects the LLM to tools — search engines, databases, APIs, calculators, code runners — so it can actually **do things**, not just talk about them.

---

### 2. Simple Concept Explanation

A plain LLM:
- Takes input
- Produces output
- Done. One step. No memory of what happened. Cannot call anything external.

An AI Agent:
- Takes input
- **Thinks** about what to do
- **Calls a tool** (search, calculate, read file)
- **Observes** the result
- **Thinks again** with new information
- Repeats until the task is complete
- Gives final answer

The LLM is still the brain. But now it has **arms and legs** — the tools.

---

---

### 4. Step-by-Step Breakdown

```
Step 1 → User sends a task to the agent

Step 2 → Agent (LLM) thinks:
         "What do I need to do to solve this?"
         "Do I need a tool?"

Step 3 → If tool needed:
         Agent outputs a structured tool call
         e.g. search_stock(ticker="AAPL")

Step 4 → Your code intercepts the tool call
         Runs the actual function
         Gets the result

Step 5 → Result is fed back to the agent as an observation

Step 6 → Agent thinks again with new information
         Decides: call another tool OR give final answer

Step 7 → Loop continues until agent decides it is done

Step 8 → Final answer returned to user
```

### 5. Code — Minimal Agent Loop (No framework)

```python
from openai import OpenAI
import json

client = OpenAI(api_key="your-api-key")

# --- Your tools (real Python functions) ---
def get_weather(city: str) -> str:
    # In reality this would call a weather API
    mock_data = {
        "London": "15°C, Cloudy",
        "New York": "22°C, Sunny",
        "Tokyo": "28°C, Humid"
    }
    return mock_data.get(city, "Weather data not available")

def calculate(operation: str, a: float, b: float) -> str:
    if operation == "add":      return str(a + b)
    if operation == "subtract": return str(a - b)
    if operation == "multiply": return str(a * b)
    if operation == "divide":   return str(a / b) if b != 0 else "Cannot divide by zero"
    return "Unknown operation"

# --- Tell the LLM what tools exist ---
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get the current weather for a city",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string", "description": "The city name"}
                },
                "required": ["city"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "calculate",
            "description": "Perform basic math: add, subtract, multiply, divide",
            "parameters": {
                "type": "object",
                "properties": {
                    "operation": {"type": "string", "enum": ["add", "subtract", "multiply", "divide"]},
                    "a": {"type": "number"},
                    "b": {"type": "number"}
                },
                "required": ["operation", "a", "b"]
            }
        }
    }
]

# --- Agent loop ---
def run_agent(user_task: str) -> str:
    messages = [{"role": "user", "content": user_task}]
    print(f"\nTask: {user_task}")
    print("=" * 50)

    for step in range(10):  # max 10 steps to prevent infinite loop
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            tools=tools,
            tool_choice="auto"
        )

        msg = response.choices[0].message
        messages.append(msg)

        # No tool call = agent is done
        if not msg.tool_calls:
            print(f"\nFinal Answer: {msg.content}")
            return msg.content

        # Process each tool call
        for tool_call in msg.tool_calls:
            fn_name = tool_call.function.name
            fn_args = json.loads(tool_call.function.arguments)

            print(f"\nStep {step + 1}:")
            print(f"  Thought → Agent wants to call: {fn_name}")
            print(f"  Args    → {fn_args}")

            # Run the actual function
            if fn_name == "get_weather":
                result = get_weather(**fn_args)
            elif fn_name == "calculate":
                result = calculate(**fn_args)
            else:
                result = "Tool not found"

            print(f"  Result  → {result}")

            # Feed result back to agent as observation
            messages.append({
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": result
            })

# --- Test it ---
run_agent("What is the weather in London and Tokyo? Also what is 15% of 847?")
```

---

### 6. Output Explanation

```
Task: What is the weather in London and Tokyo? Also what is 15% of 847?
==================================================

Step 1:
  Thought → Agent wants to call: get_weather
  Args    → {'city': 'London'}
  Result  → 15°C, Cloudy

Step 2:
  Thought → Agent wants to call: get_weather
  Args    → {'city': 'Tokyo'}
  Result  → 28°C, Humid

Step 3:
  Thought → Agent wants to call: calculate
  Args    → {'operation': 'multiply', 'a': 847, 'b': 0.15}
  Result  → 127.05

Final Answer: London is 15°C and cloudy, Tokyo is 28°C and humid.
             15% of 847 is 127.05.
```

**What happened:**
- The agent made 3 tool calls on its own — you did not tell it how many
- It decided the order and arguments by itself
- It stopped when it had everything it needed
- Your code just ran the functions and fed back results

---

### 7. Common Mistakes

| Mistake | What Happens | Fix |
|---------|-------------|-----|
| No max step limit | Agent loops forever if it gets confused | Always set a max steps guard (e.g. 10) |
| Vague tool descriptions | Agent calls wrong tool or wrong args | Write clear, specific descriptions for each tool |
| Not feeding tool result back | Agent has no observation, gets stuck | Always append tool result as a `"role": "tool"` message |
| Trusting agent args blindly | Agent may pass invalid values | Validate args before running the function |

## Concept 2 — ReAct Pattern (Reason + Act)

### 1. Real-World Problem (Hook)

You tell an agent: *"Find me the population of the capital city of the country that won the 2022 FIFA World Cup."*

A simple agent might:
- Search "2022 FIFA World Cup winner population" → gets confused results → wrong answer

A **ReAct agent** does this:
- **Reason:** "First I need to find which country won the 2022 World Cup"
- **Act:** search("2022 FIFA World Cup winner")
- **Observe:** "Argentina won"
- **Reason:** "Now I need the capital of Argentina"
- **Act:** search("capital of Argentina")
- **Observe:** "Buenos Aires"
- **Reason:** "Now I need the population of Buenos Aires"
- **Act:** search("population of Buenos Aires")
- **Observe:** "3.1 million"
- **Reason:** "I have the answer now"
- **Answer:** "Buenos Aires, the capital of Argentina, has a population of 3.1 million"

Each reasoning step **informs** the next action. That is the power of ReAct.

---

### 2. Simple Concept Explanation

ReAct = **Re**asoning + **Act**ing interleaved together.

The key idea is: **write your thinking before every action**.

Without ReAct:
```
Input → Action → Output
```

With ReAct:
```
Input → Thought → Action → Observation
      → Thought → Action → Observation
      → Thought → Final Answer
```

The **Thought** step is critical. It forces the model to plan before acting — like a chess player thinking before moving a piece.

### 4. Step-by-Step Breakdown

```
Step 1 → System prompt tells the model to think before acting
         "Always write a Thought before each Action"

Step 2 → Model generates a Thought (reasoning text)
         This is just regular text — no tool call yet

Step 3 → Model generates an Action (tool call)
         Now it actually requests a tool

Step 4 → Tool runs, returns Observation

Step 5 → Observation is added to context

Step 6 → Model generates next Thought using new information

Step 7 → Repeat until model generates Final Answer
         (no more tool calls needed)

KEY INSIGHT:
  The Thought tokens are not wasted —
  they change what the model generates next.
  Reasoning before acting = better actions.
```

### 5. Code Implementation

```python
from openai import OpenAI
import json

client = OpenAI(api_key="your-api-key")

# --- Mock search tool ---
def search(query: str) -> str:
    mock_results = {
        "2022 FIFA World Cup winner": "Argentina won the 2022 FIFA World Cup",
        "capital of Argentina": "The capital of Argentina is Buenos Aires",
        "Buenos Aires population": "Buenos Aires has a population of approximately 3.1 million in the city proper",
        "population of Buenos Aires": "Buenos Aires has a population of approximately 3.1 million"
    }
    for key in mock_results:
        if key.lower() in query.lower():
            return mock_results[key]
    return f"No results found for: {query}"

tools = [
    {
        "type": "function",
        "function": {
            "name": "search",
            "description": "Search the web for factual information",
            "parameters": {
                "type": "object",
                "properties": {
                    "query": {"type": "string", "description": "The search query"}
                },
                "required": ["query"]
            }
        }
    }
]

# --- ReAct system prompt ---
# This is what makes it ReAct — we instruct the model to reason first
react_system_prompt = """You are a helpful assistant that solves tasks step by step.

Before every action, write a brief Thought explaining what you are doing and why.
Use tools when you need information. 
When you have enough information, give a clear Final Answer.

Format:
Thought: [your reasoning here]
Action: [tool call]
Observation: [result]
...
Final Answer: [your answer]"""

def run_react_agent(question: str) -> str:
    messages = [
        {"role": "system", "content": react_system_prompt},
        {"role": "user", "content": question}
    ]

    print(f"Question: {question}\n")

    for step in range(8):
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            tools=tools,
            tool_choice="auto"
        )

        msg = response.choices[0].message
        messages.append(msg)

        # Print thought if present
        if msg.content:
            print(f"[Step {step+1}] {msg.content}")

        # No tool call = final answer
        if not msg.tool_calls:
            return msg.content

        # Run tool
        for tool_call in msg.tool_calls:
            fn_args = json.loads(tool_call.function.arguments)
            result = search(fn_args["query"])
            print(f"  → Observation: {result}\n")

            messages.append({
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": result
            })

    return "Max steps reached"

run_react_agent(
    "What is the population of the capital city of the country that won the 2022 FIFA World Cup?"
)
```

[Step 2] Thought: Argentina won. Now I need to find the capital city of Argentina.

---

### 7. Common Mistakes

| Mistake | What Happens | Fix |
|---------|-------------|-----|
| No system prompt for ReAct | Model skips Thoughts, acts blindly | Always include the Thought instruction in system prompt |
| Single broad search query | Gets confused mixed results | Teach agent to break into smaller specific searches |
| Ignoring Thought content | Missing the reasoning that shows if agent is on track | Log and monitor Thought steps in production |
| No stopping condition | Agent searches forever even after finding answer | Check if msg.tool_calls is empty to detect completion |

## Concept 3 — Function Calling (How Tools Actually Work)

### 1. Real-World Problem (Hook)

You manage a team of specialists:
- A researcher who finds information
- A calculator who does math
- A developer who writes code

When a task comes in, you do not do everything yourself. You **delegate** to the right specialist, collect their output, and combine it into a final answer.

That is exactly what **function calling** is.

The LLM is the manager. The functions are the specialists. Function calling is the delegation protocol — a structured way for the LLM to say *"I need specialist X to do job Y with these inputs Z."*

---

### 2. Simple Concept Explanation

Function calling is the mechanism by which:

1. You tell the LLM what tools exist (their names, what they do, what inputs they take)
2. The LLM decides which tool to call and with what arguments
3. The LLM outputs a structured JSON request — **it does NOT run the function itself**
4. Your code runs the actual function
5. You send the result back to the LLM
6. The LLM uses the result to continue

**Critical point:** The LLM never touches your code or database directly. It only outputs a structured request. You control what actually runs.

---

### 3. Diagram

```
YOU DEFINE (once):
┌────────────────────────────────────────┐
│ Tool: get_customer                     │
│ Description: "Get customer details     │
│              by customer ID"           │
│ Parameters:                            │
│   customer_id: string (required)       │
└────────────────────────────────────────┘

USER ASKS: "What is John Smith's email?"
                    │
                    ▼
              LLM THINKS:
    "I need customer details. I have a tool for that."
                    │
                    ▼
         LLM OUTPUTS (JSON):
    {
      "name": "get_customer",
      "arguments": {
        "customer_id": "john_smith"
      }
    }
                    │
    ← LLM stops here. Does NOT run anything. →
                    │
                    ▼
         YOUR CODE RUNS:
    get_customer("john_smith")
    → returns {"email": "john@example.com", "plan": "Premium"}
                    │
                    ▼
         YOU SEND BACK TO LLM:
    "Tool result: john@example.com, Premium plan"
                    │
                    ▼
         LLM ANSWERS:
    "John Smith's email is john@example.com.
     He is on the Premium plan."
```

---

### 4. Step-by-Step Breakdown

```
Step 1 → Define tool schemas (JSON format)
         name: what to call it
         description: what it does (LLM reads this to decide when to use it)
         parameters: what inputs it needs and their types

Step 2 → Send user message + tools list to LLM
         LLM sees both the question and available tools

Step 3 → LLM responds with either:
         a) A tool call JSON  →  it wants to use a tool
         b) Regular text     →  it has enough info to answer

Step 4 → If tool call:
         Parse the JSON
         Run your actual function with the provided arguments
         Catch any errors safely

Step 5 → Append tool result to message history
         role: "tool"
         tool_call_id: must match the id from the LLM's request

Step 6 → Send updated message history back to LLM
         LLM now has the observation and can continue
```

### 5. Code Implementation

```python
from openai import OpenAI
import json

client = OpenAI(api_key="your-api-key")

# --- Your actual functions (the specialists) ---
def get_customer(customer_id: str) -> dict:
    # In reality: query your database
    customers = {
        "C001": {"name": "John Smith",  "email": "john@example.com",  "plan": "Premium", "balance": 250.00},
        "C002": {"name": "Jane Doe",    "email": "jane@example.com",  "plan": "Basic",   "balance": 0.00},
        "C003": {"name": "Bob Johnson", "email": "bob@example.com",   "plan": "Premium", "balance": -50.00},
    }
    return customers.get(customer_id, {"error": "Customer not found"})

def get_orders(customer_id: str, limit: int = 5) -> list:
    # In reality: query your orders database
    orders = {
        "C001": [
            {"order_id": "ORD-101", "product": "Laptop",  "amount": 999.99, "status": "Delivered"},
            {"order_id": "ORD-102", "product": "Mouse",   "amount": 29.99,  "status": "Shipped"},
        ],
        "C002": [
            {"order_id": "ORD-201", "product": "Keyboard","amount": 79.99,  "status": "Processing"},
        ],
    }
    return orders.get(customer_id, [])[:limit]

def update_customer_plan(customer_id: str, new_plan: str) -> dict:
    valid_plans = ["Basic", "Premium", "Enterprise"]
    if new_plan not in valid_plans:
        return {"error": f"Invalid plan. Choose from: {valid_plans}"}
    return {"success": True, "message": f"Customer {customer_id} updated to {new_plan} plan"}

# --- Tool schemas ---
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_customer",
            "description": "Retrieve customer information including name, email, plan, and account balance",
            "parameters": {
                "type": "object",
                "properties": {
                    "customer_id": {
                        "type": "string",
                        "description": "The customer ID (format: C001, C002, etc.)"
                    }
                },
                "required": ["customer_id"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "get_orders",
            "description": "Get recent orders for a customer",
            "parameters": {
                "type": "object",
                "properties": {
                    "customer_id": {"type": "string"},
                    "limit": {
                        "type": "integer",
                        "description": "Maximum number of orders to return (default 5)"
                    }
                },
                "required": ["customer_id"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "update_customer_plan",
            "description": "Update a customer's subscription plan",
            "parameters": {
                "type": "object",
                "properties": {
                    "customer_id": {"type": "string"},
                    "new_plan": {
                        "type": "string",
                        "enum": ["Basic", "Premium", "Enterprise"]
                    }
                },
                "required": ["customer_id", "new_plan"]
            }
        }
    }
]

# --- Tool dispatcher (routes tool name to actual function) ---
def dispatch_tool(name: str, args: dict) -> str:
    if name == "get_customer":
        return json.dumps(get_customer(**args))
    elif name == "get_orders":
        return json.dumps(get_orders(**args))
    elif name == "update_customer_plan":
        return json.dumps(update_customer_plan(**args))
    return json.dumps({"error": "Unknown tool"})

# --- Agent with function calling ---
def customer_support_agent(query: str) -> str:
    messages = [
        {"role": "system", "content": "You are a helpful customer support agent. Use tools to look up customer data before answering."},
        {"role": "user", "content": query}
    ]

    for _ in range(5):
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            tools=tools,
            tool_choice="auto"
        )

        msg = response.choices[0].message
        messages.append(msg)

        if not msg.tool_calls:
            return msg.content

        for tool_call in msg.tool_calls:
            name = tool_call.function.name
            args = json.loads(tool_call.function.arguments)
            print(f"  Calling: {name}({args})")
            result = dispatch_tool(name, args)
            print(f"  Result:  {result}")

            messages.append({
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": result
            })

    return "Could not complete request"

# --- Test ---
print(customer_support_agent("What plan is customer C001 on and what are their recent orders?"))
print("\n" + "─"*50 + "\n")
print(customer_support_agent("Upgrade customer C002 to Premium plan"))
```

  Result:  {"name": "John Smith", "email": "john@example.com", "plan": "Premium", "balance": 250.0}

  Calling: get_orders({'customer_id': 'C001'})
  Result:  [{"order_id": "ORD-101", "product": "Laptop", ...}, ...]

John Smith (C001) is on the Premium plan with a balance of $250.00.

Customer C002 (Jane Doe) has been successfully upgraded to the Premium plan.

- For the second it made **1 tool call** — it knew exactly what was needed
- You never told it how many calls to make

### 7. Common Mistakes

| Mistake | What Happens | Fix |
|---------|-------------|-----|
| Weak tool description | Agent calls wrong tool or skips it | Write descriptions as if explaining to a new colleague |
| Not validating agent arguments | Bad args crash your function | Always validate before executing |
| Exposing dangerous functions | Agent deletes data or sends emails accidentally | Only expose read operations by default, gate write operations |
| Returning raw Python objects | LLM cannot read Python dicts | Always convert results to JSON string before returning |

## Concept 4 — Agent Memory Types

### 1. Real-World Problem (Hook)

You call customer support. You explain your problem for 5 minutes.

They put you on hold.

Someone else picks up. They have no idea what you said. You explain everything again.

This is what an agent without memory feels like. Every message = starts fresh. No context. No continuity.

Real agents need memory — different types for different purposes.

---

### 2. Simple Concept Explanation

There are 4 types of memory an agent can have:

| Memory Type | What It Stores | Lives How Long |
|-------------|---------------|----------------|
| **Short-term** | Current conversation messages | Until session ends |
| **Summary** | Compressed version of old conversation | Until session ends |
| **Entity** | Key facts about people/things mentioned | Until session ends or longer |
| **Long-term** | Past conversations, user preferences | Permanent, across sessions |

Think of it like a human:
- **Short-term** = what you remember from this conversation right now
- **Summary** = "we spoke last week, you mentioned X"
- **Entity** = "I know John prefers email over phone"
- **Long-term** = your notebook with client history

---

### 3. Diagram

```
SHORT-TERM MEMORY (conversation history):
┌──────────────────────────────────────────────┐
│ User: "My name is Alex"                      │
│ Agent: "Hello Alex, how can I help?"         │
│ User: "I have a billing issue"               │
│ Agent: "I can help with that Alex..."        │
│ User: "What is my name?"                     │
│ Agent: "Your name is Alex"   ← remembers     │
└──────────────────────────────────────────────┘
Limited by context window size.

─────────────────────────────────────────────

LONG-TERM MEMORY (vector database):
┌──────────────────────────────────────────────┐
│ Past Session 1 (2 weeks ago):                │
│  "Alex prefers email notifications"          │
│  "Alex is on Premium plan"                   │
│  "Alex had billing issue in March"           │
└──────────────────────────────────────────────┘
         ↓ embedded and stored in vector DB
         ↓ retrieved when relevant

New session → "Hello Alex" → retrieve Alex's profile
            → inject into context
            → agent already knows Alex's history
```

---

### 4. Step-by-Step Breakdown

```
SHORT-TERM MEMORY:
  Step 1 → Every message (user + agent) added to messages list
  Step 2 → Full list sent to LLM each turn
  Step 3 → LLM sees full conversation history
  Problem → Context window fills up after ~50-100 turns

SUMMARY MEMORY:
  Step 1 → After N messages, summarise old messages
  Step 2 → Replace old messages with summary
  Step 3 → Keep recent messages in full
  Result → Context stays manageable

ENTITY MEMORY:
  Step 1 → Extract key facts from conversation
            "User's name is Alex", "Plan: Premium", "Issue: billing"
  Step 2 → Store as structured data
  Step 3 → Prepend to context each turn
  Result → Agent always knows key facts without full history

LONG-TERM MEMORY:
  Step 1 → At session end, embed key takeaways
  Step 2 → Store vectors in database (Chroma, Pinecone, etc.)
  Step 3 → On new session, retrieve relevant memories
  Step 4 → Inject into system prompt
  Result → Agent remembers across sessions
```

### 5. Code Implementation

```python
from openai import OpenAI
from collections import defaultdict
import json

client = OpenAI(api_key="your-api-key")

# ─────────────────────────────────────────────────
# SHORT-TERM MEMORY — simplest form
# ─────────────────────────────────────────────────

class ShortTermAgent:
    def __init__(self):
        self.messages = [
            {"role": "system", "content": "You are a helpful assistant."}
        ]

    def chat(self, user_input: str) -> str:
        # Add user message to memory
        self.messages.append({"role": "user", "content": user_input})

        response = client.chat.completions.create(
            model="gpt-4o",
            messages=self.messages
        )

        reply = response.choices[0].message.content

        # Add agent reply to memory
        self.messages.append({"role": "assistant", "content": reply})

        return reply

# Test short-term memory
agent = ShortTermAgent()
print(agent.chat("My name is Alex and I love Python."))
print(agent.chat("What programming language did I mention?"))  # remembers Python
print(agent.chat("What is my name?"))                          # remembers Alex

print("\n" + "─"*50 + "\n")

# ─────────────────────────────────────────────────
# ENTITY MEMORY — extract and track key facts
# ─────────────────────────────────────────────────

class EntityMemoryAgent:
    def __init__(self):
        self.entities = {}   # stores key facts: {"name": "Alex", "plan": "Premium"}
        self.messages = []

    def extract_entities(self, conversation: str) -> dict:
        """Ask LLM to extract key facts from conversation"""
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=[
                {
                    "role": "user",
                    "content": f"""Extract key facts from this conversation as JSON.
Only include facts explicitly stated.
Format: {{"name": "...", "plan": "...", "issue": "...", "preference": "..."}}
Return only the JSON, nothing else.

Conversation:
{conversation}"""
                }
            ],
            response_format={"type": "json_object"}
        )
        return json.loads(response.choices[0].message.content)

    def build_system_prompt(self) -> str:
        base = "You are a helpful customer support agent."
        if self.entities:
            facts = "\n".join(f"- {k}: {v}" for k, v in self.entities.items() if v)
            base += f"\n\nKnown facts about this user:\n{facts}"
        return base

    def chat(self, user_input: str) -> str:
        self.messages.append({"role": "user", "content": user_input})

        # Build context with entity memory
        context = [{"role": "system", "content": self.build_system_prompt()}]
        context.extend(self.messages[-6:])  # last 3 turns only

        response = client.chat.completions.create(
            model="gpt-4o",
            messages=context
        )
        reply = response.choices[0].message.content
        self.messages.append({"role": "assistant", "content": reply})

        # Update entity memory after each turn
        recent = f"User: {user_input}\nAgent: {reply}"
        new_entities = self.extract_entities(recent)
        self.entities.update({k: v for k, v in new_entities.items() if v})

        return reply

# Test entity memory
entity_agent = EntityMemoryAgent()
print(entity_agent.chat("Hi, I am Sarah and I am on the Basic plan."))
print(f"\nExtracted entities: {entity_agent.entities}\n")
print(entity_agent.chat("I want to upgrade my plan."))
print(f"\nExtracted entities: {entity_agent.entities}\n")
print(entity_agent.chat("What plan am I currently on?"))  # knows from entity memory
```

### 6. Output Explanation

```
Hello! Nice to meet you. How can I help you today?

Extracted entities: {'name': 'Sarah', 'plan': 'Basic'}

Upgrading from Basic to Premium or Enterprise gives you access to...
I can help you with that Sarah!

Extracted entities: {'name': 'Sarah', 'plan': 'Basic', 'issue': 'upgrade plan'}

You are currently on the Basic plan, Sarah. Would you like to upgrade?
```

**What happened:**
- Short-term agent remembered across turns within a session
- Entity agent extracted "Sarah" and "Basic plan" automatically
- On the third message it used entity memory to answer correctly — even though the raw conversation was trimmed to last 3 turns

### 7. Common Mistakes

| Mistake | What Happens | Fix |
|---------|-------------|-----|
| Sending full history every turn | Context fills up, costs increase, model slows | Use summary memory or sliding window after 20+ turns |
| Only short-term memory | Agent forgets everything when session ends | Add long-term vector memory for important facts |
| Storing everything in long-term | Too much noise retrieved | Only store meaningful facts — not every message |
| No memory at all | User must repeat themselves constantly | At minimum implement short-term memory |

## Concept 5 — Multi-Agent Systems

### 1. Real-World Problem (Hook)

You need to build a report on a company:
- Research their financials online
- Write a Python script to analyse the data
- Summarise findings in a professional report
- Send it to the client via email

One agent doing all of this = slow, confused, context overload.

A **team of specialist agents** = each one does what it is best at, hands off to the next, faster and more reliable.

This is **multi-agent design**.

---

### 2. Simple Concept Explanation

Multi-agent = multiple LLM agents working together, each with a specific role.

**Supervisor pattern:**
One boss agent receives the task, breaks it down, assigns to specialists, collects results, gives final answer.

**Handoff pattern:**
Agent A completes its part and passes control directly to Agent B.

Think of it like a **relay race**:
- Runner 1 (Researcher) runs their leg → passes baton
- Runner 2 (Analyst) runs their leg → passes baton
- Runner 3 (Writer) runs their leg → crosses finish line

---

### 3. Diagram

```
SUPERVISOR PATTERN:

User Task: "Research Tesla and write a report"
                    │
                    ▼
            ┌───────────────┐
            │  SUPERVISOR   │  ← breaks task, assigns, collects
            │     AGENT     │
            └──────┬────────┘
                   │
       ┌───────────┼───────────┐
       ▼           ▼           ▼
┌─────────┐  ┌─────────┐  ┌─────────┐
│RESEARCH │  │ANALYSIS │  │ WRITER  │
│  AGENT  │  │  AGENT  │  │  AGENT  │
│(web     │  │(numbers │  │(formats │
│ search) │  │ & data) │  │ report) │
└────┬────┘  └────┬────┘  └────┬────┘
     │             │            │
     └─────────────┴────────────┘
                   │
                   ▼
            ┌───────────────┐
            │  SUPERVISOR   │  ← combines all outputs
            └───────────────┘
                   │
                   ▼
            Final Report to User
```

---

### 4. Step-by-Step Breakdown

```
Step 1 → Supervisor receives user task

Step 2 → Supervisor breaks task into subtasks
         "Research Tesla" → Research Agent
         "Analyse revenue" → Analysis Agent
         "Write report" → Writer Agent

Step 3 → Each specialist agent runs independently
         Each has its own tools and system prompt
         Each focused only on its job

Step 4 → Supervisor collects all outputs

Step 5 → Supervisor synthesises into final answer

KEY DESIGN DECISIONS:
  → Run agents in parallel when tasks are independent
  → Run in sequence when one depends on another
  → Each agent has a focused system prompt (not one giant prompt)
  → Agents share context only what is needed — not everything
```

### 5. Code Implementation

```python
from openai import OpenAI
import json

client = OpenAI(api_key="your-api-key")

# --- Specialist Agents ---

def research_agent(topic: str) -> str:
    """Agent specialised in finding information"""
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {
                "role": "system",
                "content": "You are a research specialist. Find and summarise key facts about the given topic. Be concise and factual."
            },
            {
                "role": "user",
                "content": f"Research this topic and give me 5 key facts: {topic}"
            }
        ]
    )
    return response.choices[0].message.content

def analysis_agent(data: str) -> str:
    """Agent specialised in analysis and insights"""
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {
                "role": "system",
                "content": "You are a data analyst. Analyse the given information and provide 3 key insights and trends."
            },
            {
                "role": "user",
                "content": f"Analyse this information and provide insights:\n\n{data}"
            }
        ]
    )
    return response.choices[0].message.content

def writer_agent(research: str, analysis: str, topic: str) -> str:
    """Agent specialised in writing professional reports"""
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {
                "role": "system",
                "content": "You are a professional business writer. Write clear, structured, professional reports."
            },
            {
                "role": "user",
                "content": f"""Write a short professional report on: {topic}

Research findings:
{research}

Analysis insights:
{analysis}

Format: Executive Summary, Key Facts, Analysis, Conclusion"""
            }
        ]
    )
    return response.choices[0].message.content

def supervisor_agent(user_task: str) -> str:
    """Supervisor that orchestrates all specialist agents"""
    print(f"Task received: {user_task}\n")

    # Extract topic from task
    topic = user_task

    # Step 1: Research (could run in parallel with other independent tasks)
    print("→ Research Agent working...")
    research = research_agent(topic)
    print(f"  Done. ({len(research)} chars)\n")

    # Step 2: Analysis (needs research first)
    print("→ Analysis Agent working...")
    analysis = analysis_agent(research)
    print(f"  Done. ({len(analysis)} chars)\n")

    # Step 3: Write report (needs both research and analysis)
    print("→ Writer Agent working...")
    report = writer_agent(research, analysis, topic)
    print(f"  Done. ({len(report)} chars)\n")

    return report

# --- Run it ---
final_report = supervisor_agent("Tesla's electric vehicle business and market position")
print("=" * 60)
print("FINAL REPORT:")
print("=" * 60)
print(final_report)
```

### 7. Common Mistakes

| Mistake | What Happens | Fix |
|---------|-------------|-----|
| One giant prompt for everything | Context overload, confused outputs | Split into specialist agents with focused prompts |
| Running sequential when parallel is possible | Slow performance | Identify independent tasks and run them simultaneously |
| Agents share too much context | Noise degrades quality | Each agent receives only what it needs |
| No supervisor to synthesise | Fragmented outputs never combined | Always have a final synthesis step |

## Concept 6 — LangChain & LangGraph Basics

### 1. Real-World Problem (Hook)

Building an agent from scratch (like we did in previous concepts) means:
- Writing the tool schema JSON by hand
- Manually managing the message loop
- Building memory from scratch
- Handling errors yourself

For a prototype that is fine. For a production system with 10 tools, 3 agent types, conditional routing, and retry logic — it becomes a massive amount of repetitive code.

**LangChain** and **LangGraph** are frameworks that give you these building blocks ready-made so you focus on your logic, not the plumbing.

---

### 2. Simple Concept Explanation

**LangChain:**
A toolkit of pre-built components — tools, memory, chains, document loaders, output parsers. Think of it as a library of Lego bricks for building LLM applications.

**LangGraph:**
Built on LangChain. Lets you define agent behaviour as a **graph** — nodes are actions, edges are conditions. Like a flowchart your agent follows.

```
LangChain  = individual components (bricks)
LangGraph  = how you connect them with control flow (the blueprint)
```

---

### 3. Diagram

```
LANGCHAIN COMPONENTS:
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│   LLM        │  │   Tools      │  │   Memory     │
│  (GPT-4o,    │  │  (Search,    │  │  (Buffer,    │
│   Claude)    │  │   Calculator)│  │   Vector DB) │
└──────────────┘  └──────────────┘  └──────────────┘
       ↓                 ↓                  ↓
┌─────────────────────────────────────────────────┐
│              LANGCHAIN AGENT                    │
│  Combines LLM + Tools + Memory automatically    │
└─────────────────────────────────────────────────┘

─────────────────────────────────────────────────

LANGGRAPH — STATEFUL GRAPH:

         ┌─────────┐
         │  START  │
         └────┬────┘
              │
              ▼
        ┌──────────┐
        │  Agent   │ ← decides what to do
        └────┬─────┘
             │
     ┌───────┴────────┐
     ▼                ▼
┌─────────┐     ┌──────────┐
│ call    │     │   END    │ ← if no tool needed
│  tool   │     └──────────┘
└────┬────┘
     │
     ▼
┌─────────┐
│  tool   │ ← runs the tool
│ result  │
└────┬────┘
     │
     └──────────► back to Agent (loop)
```

---

### 4. Step-by-Step Breakdown

```
LANGCHAIN AGENT STEPS:
Step 1 → Define your tools using @tool decorator
Step 2 → Create LLM instance (ChatOpenAI)
Step 3 → Bind tools to LLM
Step 4 → Create agent with prompt template
Step 5 → Run agent — LangChain handles the loop

LANGGRAPH STEPS:
Step 1 → Define state (what information flows through the graph)
Step 2 → Define nodes (functions for each step)
Step 3 → Define edges (which node goes to which, under what condition)
Step 4 → Compile graph
Step 5 → Invoke with initial state — graph runs the flow
```

### 5. Code Implementation

```python
# pip install langchain langchain-openai langgraph

# ─────────────────────────────────────────────────
# LANGCHAIN — Simple Agent with Tools
# ─────────────────────────────────────────────────

from langchain_openai import ChatOpenAI
from langchain.agents import create_tool_calling_agent, AgentExecutor
from langchain_core.tools import tool
from langchain_core.prompts import ChatPromptTemplate
import math

# --- Define tools with @tool decorator ---
@tool
def calculator(expression: str) -> str:
    """Evaluate a mathematical expression. Example: '2 + 2' or 'sqrt(16)'"""
    try:
        # Safe eval for math only
        allowed = {k: v for k, v in math.__dict__.items() if not k.startswith("_")}
        result = eval(expression, {"__builtins__": {}}, allowed)
        return str(result)
    except Exception as e:
        return f"Error: {e}"

@tool
def get_weather(city: str) -> str:
    """Get current weather for a city"""
    mock = {"London": "15°C Cloudy", "Paris": "20°C Sunny", "Tokyo": "28°C Humid"}
    return mock.get(city, "Weather unavailable")

# --- Create LangChain agent ---
llm = ChatOpenAI(model="gpt-4o", api_key="your-api-key")
tools = [calculator, get_weather]

prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful assistant. Use tools when needed."),
    ("human", "{input}"),
    ("placeholder", "{agent_scratchpad}")
])

agent = create_tool_calling_agent(llm, tools, prompt)
executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

# --- Run it ---
result = executor.invoke({"input": "What is sqrt(144) and what is the weather in Paris?"})
print(result["output"])

print("\n" + "─"*50 + "\n")

# ─────────────────────────────────────────────────
# LANGGRAPH — Stateful Agent Graph
# ─────────────────────────────────────────────────

from langgraph.graph import StateGraph, END
from langgraph.prebuilt import ToolNode
from langchain_core.messages import HumanMessage
from typing import TypedDict, Annotated
import operator

# Define state — what travels through the graph
class AgentState(TypedDict):
    messages: Annotated[list, operator.add]

# Bind tools to LLM
llm_with_tools = llm.bind_tools(tools)

# Node 1: Agent node — LLM decides what to do
def agent_node(state: AgentState) -> AgentState:
    response = llm_with_tools.invoke(state["messages"])
    return {"messages": [response]}

# Conditional edge — should we call a tool or end?
def should_continue(state: AgentState) -> str:
    last_message = state["messages"][-1]
    if last_message.tool_calls:
        return "tools"   # go to tool node
    return END           # we are done

# Node 2: Tool node — runs the tools
tool_node = ToolNode(tools)

# Build the graph
graph = StateGraph(AgentState)
graph.add_node("agent", agent_node)
graph.add_node("tools", tool_node)

graph.set_entry_point("agent")
graph.add_conditional_edges("agent", should_continue)
graph.add_edge("tools", "agent")   # after tools, go back to agent

app = graph.compile()

# --- Run LangGraph agent ---
result = app.invoke({
    "messages": [HumanMessage(content="What is 25 * 48 and the weather in London?")]
})

print("LangGraph Final Answer:")
print(result["messages"][-1].content)
```

```
LangChain Agent (verbose=True):
> Entering new AgentExecutor chain...
  Invoking calculator with {'expression': 'sqrt(144)'}
  → 12.0
  Invoking get_weather with {'city': 'Paris'}
  → 20°C Sunny
> Finished chain.

The square root of 144 is 12.0.
The weather in Paris is currently 20°C and Sunny.

──────────────────────────────────────────────────

LangGraph Final Answer:
25 * 48 = 1200.
The weather in London is currently 15°C and Cloudy.
```

**LangChain handled:**
- Tool schema generation (from the `@tool` decorator)
- The agent loop automatically
- Verbose logging for debugging

**LangGraph handled:**
- State management between nodes
- Conditional routing (tool vs end)
- The loop back from tool → agent automatically

### 7. Common Mistakes

| Mistake | What Happens | Fix |
|---------|-------------|-----|
| Using LangChain for simple single-step tasks | Overkill, harder to debug | Use raw OpenAI API for simple cases |
| Skipping LangGraph for complex multi-step agents | Manual loop logic becomes unmanageable | Use LangGraph when you need conditional routing or branching |
| Not using `verbose=True` during development | Cannot see what the agent is doing | Always enable verbose during development |
| Storing sensitive data in LangGraph state | Security risk | Never put passwords, tokens, or PII in state |

## Concept 7 — Agent Evaluation

### 1. Real-World Problem (Hook)

You deploy your customer support agent to production. Your manager asks:

*"Is it working well? How do we know?"*

You say: *"It seems fine..."*

That is not good enough. You need **numbers**. Metrics. Evidence that the agent is doing its job correctly, efficiently, and safely.

Without evaluation you cannot improve what you cannot measure.

---

### 2. Simple Concept Explanation

Agents are harder to evaluate than plain LLMs because they:
- Make multiple decisions (which tool to call?)
- Take multiple steps (did it take too many?)
- Can fail in many ways (wrong tool, wrong args, stuck in loop)

You need metrics at **three levels**:

| Level | What You Measure |
|-------|-----------------|
| Task level | Did it complete the task correctly? |
| Process level | How efficiently did it get there? |
| Safety level | Did it behave safely throughout? |

---

### 3. Diagram

```
AGENT EVALUATION DIMENSIONS:

┌──────────────────────────────────────────────┐
│  TASK SUCCESS                                │
│  Did the agent complete the task?            │
│  Metric: Success Rate (correct / total)      │
└──────────────────────────────────────────────┘

┌──────────────────────────────────────────────┐
│  EFFICIENCY                                  │
│  How many steps did it take?                 │
│  Metric: Avg steps to completion             │
│  Did it pick the right tools?                │
│  Metric: Tool selection accuracy             │
└──────────────────────────────────────────────┘

┌──────────────────────────────────────────────┐
│  SAFETY                                      │
│  Did it call dangerous functions?            │
│  Did it hallucinate tool arguments?          │
│  Metric: Error rate, safety violation rate   │
└──────────────────────────────────────────────┘
```

---

### 4. Step-by-Step Breakdown

```
Step 1 → Define a test set
         A list of tasks with known correct answers
         Example: {"task": "Get weather in London", "expected_tool": "get_weather", "expected_city": "London"}

Step 2 → Run agent on each test case

Step 3 → Record for each run:
         - Did it succeed? (yes/no)
         - How many steps did it take?
         - Which tools did it call?
         - What arguments did it pass?
         - Did it error or loop?

Step 4 → Calculate metrics:
         Success rate = correct completions / total tests
         Avg steps = total steps / total tests
         Tool accuracy = correct tool calls / total tool calls

Step 5 → Compare across versions
         "Agent v2 has 92% success rate vs v1 at 78%"

Step 6 → Identify failure patterns
         "Agent always fails when city name has a typo"
         Fix the issue, re-evaluate
```

---

### 5. Code Implementation

```python
from openai import OpenAI
import json
import time

client = OpenAI(api_key="your-api-key")

# --- Reuse tools from earlier ---
def get_weather(city: str) -> str:
    mock = {"London": "15°C Cloudy", "Paris": "20°C Sunny", "Tokyo": "28°C Humid"}
    return mock.get(city, "Weather unavailable")

def calculate(operation: str, a: float, b: float) -> str:
    ops = {"add": a+b, "subtract": a-b, "multiply": a*b, "divide": a/b if b else None}
    result = ops.get(operation)
    return str(result) if result is not None else "Error"

tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get current weather for a city",
            "parameters": {
                "type": "object",
                "properties": {"city": {"type": "string"}},
                "required": ["city"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "calculate",
            "description": "Perform basic math: add, subtract, multiply, divide",
            "parameters": {
                "type": "object",
                "properties": {
                    "operation": {"type": "string"},
                    "a": {"type": "number"},
                    "b": {"type": "number"}
                },
                "required": ["operation", "a", "b"]
            }
        }
    }
]

def dispatch(name, args):
    if name == "get_weather": return get_weather(**args)
    if name == "calculate":   return calculate(**args)
    return "Unknown tool"

# --- Run agent and collect metrics ---
def evaluate_agent(task: str, expected_tools: list) -> dict:
    messages = [{"role": "user", "content": task}]
    steps = 0
    tools_called = []
    errors = []
    start_time = time.time()

    for _ in range(8):
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            tools=tools,
            tool_choice="auto"
        )
        msg = response.choices[0].message
        messages.append(msg)

        if not msg.tool_calls:
            break

        for tool_call in msg.tool_calls:
            steps += 1
            name = tool_call.function.name
            args = json.loads(tool_call.function.arguments)
            tools_called.append(name)

            try:
                result = dispatch(name, args)
            except Exception as e:
                result = f"Error: {e}"
                errors.append(str(e))

            messages.append({
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": result
            })

    elapsed = time.time() - start_time
    final_answer = messages[-1].content if hasattr(messages[-1], 'content') else str(messages[-1])

    # Evaluate correctness
    correct_tools = all(t in tools_called for t in expected_tools)

    return {
        "task": task,
        "success": correct_tools and len(errors) == 0,
        "steps": steps,
        "tools_called": tools_called,
        "expected_tools": expected_tools,
        "tool_accuracy": correct_tools,
        "errors": errors,
        "latency_seconds": round(elapsed, 2),
        "answer_preview": (final_answer or "")[:100]
    }

# --- Test suite ---
test_cases = [
    {"task": "What is the weather in London?",          "expected_tools": ["get_weather"]},
    {"task": "What is 25 multiplied by 48?",            "expected_tools": ["calculate"]},
    {"task": "Weather in Paris and 10% of 500?",        "expected_tools": ["get_weather", "calculate"]},
    {"task": "What is the capital of France?",          "expected_tools": []},  # no tool needed
]

# --- Run evaluation ---
results = []
for case in test_cases:
    r = evaluate_agent(case["task"], case["expected_tools"])
    results.append(r)

# --- Report ---
print(f"\n{'='*60}")
print(f"AGENT EVALUATION REPORT")
print(f"{'='*60}")
print(f"Total tests:    {len(results)}")
print(f"Success rate:   {sum(r['success'] for r in results) / len(results) * 100:.0f}%")
print(f"Avg steps:      {sum(r['steps'] for r in results) / len(results):.1f}")
print(f"Avg latency:    {sum(r['latency_seconds'] for r in results) / len(results):.2f}s")
print(f"\nPer-test results:")
for r in results:
    status = "PASS" if r['success'] else "FAIL"
    print(f"  [{status}] {r['task'][:45]:45} steps={r['steps']} tools={r['tools_called']}")
```

### 7. Common Mistakes

| Mistake | What Happens | Fix |
|---------|-------------|-----|
| No evaluation at all | You deploy blindly and find out in production | Always build a test suite before deploying |
| Only checking final answer | Misses cases where agent got right answer wrong way | Also track steps and tool calls |
| Test suite too small | High scores that do not reflect real performance | Minimum 50–100 diverse test cases |
| Never re-running evals after changes | Regressions go undetected | Run evals on every code or prompt change |
