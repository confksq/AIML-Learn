what is ai agent vs agentic ai

## Claude

Good question — this is a real interview discriminator, and most people fumble it because the market uses both terms as synonyms. They aren't.

## The one-line answer

| | What it is | Part of speech |
|---|---|---|
| **AI Agent** | A **thing** — one unit: LLM + loop + tools + stopping condition | a **noun** — a component |
| **Agentic AI** | A **property** — a system where the *model*, not your code, decides what happens next | an **adjective** — a design paradigm |

An AI agent is the smallest unit that *has* agency. Agentic AI is the whole design philosophy of building systems that way.

## The real discriminator: who owns control flow?

This is the test that actually settles it:

```
  WORKFLOW / CHAIN                    AGENTIC
  ────────────────                    ───────
  YOU wrote the sequence.             THE MODEL picks the sequence
  Step 1 → Step 2 → Step 3            at runtime, every run.

  if (refund > 2000) approve();       "Here are 5 tools and a goal.
  Deterministic. Same path            Figure it out."
  every single time.                  Different path per input.

  Control flow lives in YOUR CODE     Control flow lives in THE LLM
```

If you can draw the flowchart before running it → **workflow**.
If the flowchart is different each time depending on what the model decides → **agentic**.

## Your JM Family cancellation task, three points on the spectrum

Same business goal — cancel a VSC contract. Three architectures:

**1. Not agentic — plain C#**
```
ReadEmail() → ParseVIN() → LookupContract() → CalcRefund() → Submit()
```
Hardcoded. No LLM. Fast, cheap, auditable. *This is still the right answer for most JM Family work* — the point you pushed back on in the 07-23 session, correctly.

**2. An AI agent** — one agent, tool-calling loop
> "Here's a dealer email. Tools: `LookupContract`, `CalcRefund`, `SubmitCancellation`. Handle it."

The model decides: *do I need the contract first? Is this even a cancellation? The refund looks odd — let me re-check mileage.* You never wrote that ordering. **One agent = an AI agent.**

**3. Agentic AI** — a system exhibiting agency
An intake agent classifies the email → routes to a cancellation agent *or* a claims agent → cancellation agent delegates refund math to a pricing agent (A2A) → a supervisor agent checks the result → a human gate fires above $2,000 → state checkpoints so it survives restart.

Agents delegating to agents, planning, memory, recovery. **That's agentic AI** — the property of the whole system, not any one agent in it.

## The library's autonomy ladder

Your own `VitalCare` assessment (`05_Assessments/VitalCare_AI_Assessment_Response.md:1441`) has the best framing you own — "agentic" isn't binary, it's a dial:

```
L1  Human does everything (no AI)
L2  AI suggests · human decides AND acts     ← barely agentic
L3  AI decides · human reviews before action  ← the enterprise sweet spot
L4  AI acts · human can intervene in a window ← reversible actions only
L5  Fully autonomous, no human               ← not appropriate for
```

```
you deployed.                       deployed.

Azure Resource Manager owns         A tfstate file owns it.
the deployment record.              You store it (blob / S3),

No "state file" concept exists.     State is an artifact you manage.
```

Here are your five terms directly:

## 1. DSL = Domain-Specific Language

A language built for **one job only**.

| | Example | Could you write a web app in it? |
|---|---|---|
| General-purpose | C#, Python, Go | Yes |
| **DSL** | **Bicep**, HCL, SQL | **No** — Bicep only describes Azure resources |

And Bicep isn't a runtime — it **transpiles** to ARM JSON, which is what Azure actually executes:

```
main.bicep ──(bicep build)──► main.json (ARM) ──► Azure Resource Manager ──► resources
 you write                      generated
```

## 2. Cross-cloud Terraform

One language, one CLI, many clouds — via plug-ins called **providers**:

```hcl
provider "azurerm" {}              provider "aws" {}
resource "azurerm_storage_account" resource "aws_s3_bucket"
```

Both can sit in the *same file*; one `apply` provisions across both. Bicep can never do this — it speaks only ARM.

⚠️ Terraform unifies the **workflow and language**, not the cloud APIs. You still have to know each cloud.

## 3. CFN service = CloudFormation

AWS's native IaC service — the direct equivalent of Azure Resource Manager. You hand it a YAML template; it creates the resources and **remembers what it created**. It's a running service with a console and event log, not just a file format.

## 4. `tfstate` = Terraform's memory

```
your code:  resource "aws_s3_bucket" "logs" {...}
                        ↕  tfstate remembers this pairing
real cloud: arn:aws:s3:::jma-logs-20260726
```

**This is the one genuinely new concept for you.** Bicep never made you learn it because Azure keeps that record inside ARM. With Terraform *you* own it — which brings remote backends, state locking, and this gotcha:

> **State stores resource attributes in plaintext — including passwords and keys.** Treat the state file as a secret. Bicep devs routinely don't know this, and it's a common interview probe.

## 5. Stack

AWS's **unit of deployment** — a named set of resources from one template, managed together. Delete the stack, all its resources go.

| Azure | AWS | GCP | Terraform |
|---|---|---|---|
| Deployment / Deployment Stack | **Stack** | Deployment | State / workspace |

⚠️ Overloaded word: Pulumi uses "stack" to mean *environment* (dev stack, prod stack).
